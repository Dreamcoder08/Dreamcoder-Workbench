## L3 headless GTK runtime probe (private evidence)

Toolchain: GTK 3.24.52, GTK 4.22.5, libadwaita 1.9, `gtk4-broadwayd`/`broadwayd` headless backends, system Python 3.13 with PyGObject and PyQt6. Probe scripts and PNG snapshots live in `/home/dreamcoder08/.tmp/opencode/gtkprobe` (private, not checked in). No live desktop state was read into the probe or changed by it.

Method: load the canonical `DreamcoderThemes/dreamcoder/gtk-dark.css` through the real user path, that is a private `XDG_CONFIG_HOME` whose `gtk-3.0/gtk.css` and `gtk-4.0/gtk.css` only `@import` the asset, then read resolved widget colors. Separate runs loaded the same file as an application-priority provider. Pixel snapshots used `Gtk.WidgetPaintable`, `Gsk.CairoRenderer.render_texture` and `Gdk.Texture.save_to_png`, and the PNGs were sampled with GdkPixbuf. Each surface was compared against a no-asset baseline and against a control that adds one explicit rule.

| Surface | Measurement | Canonical asset | Control |
| --- | --- | --- | --- |
| Plain GTK4 `Gtk.ApplicationWindow` | `label.get_color()` | rgb(46,52,54) | same as baseline; `label { color: #abcdef; }` gives rgb(171,205,239) |
| Plain GTK4 pixels | content center of a 203x120 snapshot | rgb(246,245,244) | byte-identical to baseline; `window { background-color: #0B0B0B; }` gives rgb(11,11,11) |
| Plain GTK3 3.24.52 `Gtk.Window` | `get_style_context().get_color(NORMAL)` | rgb(46,52,54) | same as baseline; the explicit rule applies |
| libadwaita 1.9 `Adw.ApplicationWindow` | `label.get_color()` | rgb(230,230,230) = `#E6E6E6` | rgb(255,255,255) without the import |

Interpretation: a stylesheet made only of `@define-color` statements is honoured by libadwaita applications, which is the GTK4 GNOME surface. Plain GTK3 and plain non-Adw GTK4 resolve their theme colors inside the theme provider and ignore the imported definitions, so those surfaces keep Adwaita colors. The GTK3 Dark surface is therefore registered and reversible but visually inert, and so is non-Adw GTK4. qt6ct is a real palette configuration rather than a stylesheet and was not part of this probe.

Limitations: synthetic widget trees on a headless Broadway backend, not real application screenshots. No hover, backdrop, menu, tooltip, selected-row or disabled-state evidence; no device glare, comfort or live activation. Parsing without visual effect is the finding, not a parse failure.

Decision 2026-10-23: the user chose to document the measured reach as the contract instead of extending the asset with widget rules. The user-facing description lives in `docs/configuration/theme-system.md`, section "GTK and Qt".
