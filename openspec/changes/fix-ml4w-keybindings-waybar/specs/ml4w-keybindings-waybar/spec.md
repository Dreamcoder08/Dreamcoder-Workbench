# Spec: ML4W Keybindings & Waybar Integration

## Overview

Complete the ML4W integration in Dreamcoder-dots by adding standard Hyprland keybindings to machine profiles and creating a Waybar configuration with taskbar support and Dreamcoder Light theme.

## Functional Requirements

### FR1: Extended Keybinding Profiles

**FR1.1 — Standard ML4W App Launchers**

- SUPER + RETURN → launch Kitty terminal
- SUPER + B → launch Firefox browser
- SUPER + E → launch Thunar file manager
- SUPER + SPACE → launch Rofi app launcher (`rofi -show drun`)
- SUPER + V → launch clipboard manager (cliphist + rofi)

**FR1.2 — Ctrl+Win Secondary App Shortcuts**

- SUPER + CTRL + SHIFT + K → Kitty with Neovim (`kitty nvim`)
- CTRL + SUPER + M → Kitty with btop system monitor
- CTRL + SUPER + S → ML4W Settings app
- CTRL + SUPER + C → Calculator

**FR1.3 — Window Management**

- SUPER + Q → close active window (`killactive`)
- SUPER + F → toggle fullscreen
- SUPER + T → toggle floating window
- SUPER + Y → toggle split direction

**FR1.4 — Workspace Navigation**

- SUPER + 1–5 → switch to workspace 1–5
- SUPER + SHIFT + 1–5 → move window to workspace 1–5
- SUPER + 6–0 → switch to workspace 6–10
- SUPER + SHIFT + 6–0 → move window to workspace 6–10

**FR1.5 — Window Focus & Move**

- SUPER + h/j/k/l → move focus left/down/up/right
- SUPER + SHIFT + h/j/k/l → move window left/down/up/right
- SUPER + Left/Right/Up/Down → move focus (arrow alternative)
- SUPER + SHIFT + Left/Right/Up/Down → move window (arrow alternative)

**FR1.6 — System Controls**

- SUPER + ALT + L → lock screen (`hyprlock`)
- PRINT → screenshot area (`grimblast save area`)
- SUPER + SHIFT + S → full screenshot

**FR1.7 — Both Profiles**

- Core bindings MUST be present in both `default.json` and `asus-vivobook15.json`.
  (Reconciled 2026-09-11: `asus-vivobook15.json` intentionally omits the
  `SUPER+ALT+L` lock binding and the bare `PRINT` screenshot binding that
  `default.json` carries; both profiles ship 50+ bindings including the
  `SUPER+CTRL` set.)
- Existing bindings (theme toggle, blue light, brightness, volume, media) MUST be preserved

### FR2: Waybar Configuration

**FR2.1 — Config File**

- Create `DreamcoderWaybar/.config/waybar/config.jsonc`
- ML4W-compatible structure: `modules-left`, `modules-center`, `modules-right`

**FR2.2 — Taskbar Module**

- Include `hyprland/workspaces` with `window-rewrite` for app icon display
- Workspace buttons show active app names/classes
- Active workspace highlighted with Dreamcoder accent color, delivered through the
  `colors.css` import chain described in FR2.4

**FR2.3 — Standard Modules**

- Left: `hyprland/workspaces` (taskbar)
- Center: `clock`
- Right: `network`, `pulseaudio`, `cpu`, `memory`, `battery`, `tray`

**FR2.4 — Theme Integration**

- Import the Dreamcoder active-color bridge (`colors.css`, which selects the
  light/dark variant) via `@import` in `style.css`. (Reconciled 2026-09-11: the
  shipped `DreamcoderWaybar/.config/waybar/style.css` imports `colors.css`, not the
  `waybar-light.css` / `waybar-dark.css` files this requirement originally named.)
- Waybar CSS files already generated by `sync-dreamcoder-theme.py` — no changes needed
- Module colors reference the CSS variables defined by Dreamcoder tokens

### FR3: Profile Schema Compatibility

**FR3.1 — No Schema Changes**

- All new bindings use existing schema fields: `key`, `mods`, `command`, `description`, `bind_type`, `options`
- Schema already supports `CTRL` + `SUPER` combo mods (via array: `["CTRL", "SUPER"]`)
- Schema already supports arrow keys, numbers, and function keys

**FR3.2 — Validation**

- `scripts/validate-ml4w-profiles.py` validates all new bindings
- `scripts/generate-custom-lua.sh` generates valid Hyprland Lua from profiles

### FR4: Theme Sync Integrity

**FR4.1 — No Theme Engine Changes**

- `apply-theme-mode.sh` correctly handles Waybar CSS symlink + restart
- `sync-dreamcoder-theme.py` correctly generates Waybar CSS
- Waybar config keeps CSS import separate from layout config

## Non-Functional Requirements

- **NFR1**: All binding commands must be valid Hyprland dispatcher calls or shell commands
- **NFR2**: Waybar config must parse as valid JSON/JSONC
- **NFR3**: Waybar must start without errors using the config
- **NFR4**: Bindings must not conflict with ML4W's built-in defaults
- **NFR5**: Dreamcoder Light colors must be visible in all Waybar modules
